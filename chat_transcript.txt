### How This Project Works

This project is an AI-powered financial decision engine designed for the HackerRank **Orchestrate — "Buy or Wait?"** challenge. It evaluates whether a user can safely afford a financial request (e.g., purchasing a laptop, travel, tuition, debt repayment, investment) over a **90-day forward-looking horizon** without breaching their personalized minimum balance requirement.

```mermaid
flowchart TD
    A[Dataset CSVs] --> B[Data Loader & FX Engine]
    M[Messages & Images] --> C[Evidence Router]
    C -->|Vision Cache / Regex Directives| D[Financial State Reconstructor]
    B --> D
    D --> E[90-Day Forecast Engine]
    E -->|Binary Search & Daily Scan| F[amount_safe_to_pay & earliest_date]
    F --> G[Candidate Planner & 6-Rule Ranker]
    G --> H[Deterministic Verifier]
    H --> I[Explanation Generator]
    I --> J[output.csv & usage_report.md]
```

### Core Pipeline Components

#### 1. Data Ingestion & FX Conversion ([`data_loader.py`](file:///c:/Others/Projects/HackerRank-Orchestrate/code/src/data_loader.py), [`fx.py`](file:///c:/Others/Projects/HackerRank-Orchestrate/code/src/fx.py))
- Ingests and indexes the 7 input CSVs (`requests.csv`, `financial_profiles.csv`, `financial_events.csv`, `exchange_rates.csv`, `request_payment_options.csv`, `messages.csv`, `images.csv`).
- Handles multi-currency transactions across INR, ZAR, IDR, USD, and EUR using a graph-based pathfinder with dated conversion rates.

#### 2. Multimodal Evidence Resolution ([`evidence.py`](file:///c:/Others/Projects/HackerRank-Orchestrate/code/src/evidence.py), [`message_rules.py`](file:///c:/Others/Projects/HackerRank-Orchestrate/code/src/message_rules.py), [`vision_cache.json`](file:///c:/Others/Projects/HackerRank-Orchestrate/code/cache/vision_cache.json))
- **Images (Vision)**: Scanned receipts and payslips linked to blank-`amount` events are resolved through `vision_cache.json` (with live vision LLM fallback capability if `LLM_API_KEY` is configured).
- **Messages (Text)**: A deterministic bilingual (English/Indonesian) regex rule engine extracts structured directives (e.g., salary raises, temporary pay cuts, settled payments, subscription cancellations).
- **Adversarial Safety**: Automatically ignores malicious / phishing messages (e.g., "pay a release fee for a lottery prize") so they never corrupt user financials.

#### 3. Financial State Reconstruction ([`events.py`](file:///c:/Others/Projects/HackerRank-Orchestrate/code/src/events.py))
- Merges starting available balance with evidence directives.
- Distinguishes **explicit future dated events** from historical recurring series (salary, rent, utilities, subscriptions).
- Identifies spending flexibility (`stoppable`, `reducible`, `protected`) for what-if scenario generation.

#### 4. 90-Day Forecast Simulation ([`forecast.py`](file:///c:/Others/Projects/HackerRank-Orchestrate/code/src/forecast.py))
- Performs exact, day-by-day cash flow simulation using `Decimal` arithmetic.
- Uses **binary search** to determine `amount_safe_to_pay` (the maximum lump sum safe on `request_date`).
- Uses a **day-by-day linear scan** to identify `earliest_date_for_full_payment` (the first date a full lump sum can be safely paid).

#### 5. Candidate Generation & 6-Tier Ranking ([`planner.py`](file:///c:/Others/Projects/HackerRank-Orchestrate/code/src/planner.py))
- Generates all valid plans allowed by user preferences (`full_payment`, `wait`, `partial_payment`, `installments`, and combinations with up to 3 spending cuts).
- Ranks candidate plans using the problem statement's tie-breaking rules:
  1. Complete the request by `desired_completion_date`
  2. Require no spending changes
  3. Minimize total amount paid
  4. Start payments earlier
  5. Use fewer payments
  6. Smallest `payment_option_id` (final tie-breaker)

#### 6. Deterministic Verifier & Explainer ([`verifier.py`](file:///c:/Others/Projects/HackerRank-Orchestrate/code/src/verifier.py), [`explain.py`](file:///c:/Others/Projects/HackerRank-Orchestrate/code/src/explain.py))
- **Safety Gate**: Re-simulates the chosen plan against the user's cash flow. Any failing plan is downgraded to `not_recommended` / `not_affordable`.
- **Explanations**: Produces clear natural language explanations with key financial metrics (minimum balance reached, safety thresholds, and justification).

---

### Output Columns Generated

Each evaluated request produces:
- `amount_safe_to_pay`: Safe amount payable on `request_date`.
- `affordability_status`: `affordable_now`, `affordable_with_plan`, `affordable_later`, or `not_affordable`.
- `recommended_payment_method`: `full_payment`, `partial_payment`, `installments`, `wait`, or `not_recommended`.
- `payment_plan`: Formatted schedule (e.g. `2026-09-07:300|2026-10-07:300` or `none`).
- `earliest_date_for_full_payment`: First safe full-payment date.
- `spending_changes_needed`: Spending adjustments (e.g. `stop:event_14|reduce_to:event_21:100` or `none`).
- `decision_explanation`: Summary justifying the recommendation.
